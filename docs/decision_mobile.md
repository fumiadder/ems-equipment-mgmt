# 技术决策记录 — 移动端技术方案

## 决策编号
OI-04

## 背景
点巡检模块需要移动端支持，巡检人员在车间现场使用。设计文档中推荐 PWA 方案，需评估是否满足需求或需要切换到原生方案。

## 功能需求分析

| 功能需求 | PWA | React Native | Flutter |
|----------|-----|---------------|---------|
| 巡检任务列表展示 | ✅ | ✅ | ✅ |
| 检查项录入（数值/文字/是否） | ✅ | ✅ | ✅ |
| 拍照上传 | ✅（有限制） | ✅ | ✅ |
| 离线巡检（断网时继续工作） | ✅（IndexedDB + Service Worker） | ✅（AsyncStorage/SQLite） | ✅（SQLite） |
| 二维码/条形码扫描 | ⚠️（需要第三方库，体验一般） | ✅（原生体验） | ✅（原生体验） |
| NFC 标签读取（设备识别） | ❌ | ✅ | ✅ |
| 蓝牙连接（传感器直连） | ❌ | ✅ | ✅ |
| 后台定位（自动记录巡检轨迹） | ⚠️（受限） | ✅ | ✅ |
| 推送通知 | ⚠️（受限） | ✅ | ✅ |
| 安装到主屏幕 | ✅ | ✅（应用商店） | ✅（应用商店） |
| 开发成本 | 低（复用 Web 技术栈） | 中（需独立开发） | 中（需独立开发） |
| 与前端团队技术栈一致性 | ✅ 高（React 复用） | ✅ 中（React 复用） | ❌ 低（Dart 语言） |

## 候选方案对比

| 维度 | PWA | React Native | Flutter |
|------|-----|---------------|---------|
| **开发周期** | 2-3 周 | 4-6 周 | 6-8 周 |
| **开发成本** | 低（1 名前端即可） | 中（需 1-2 名移动开发） | 中（需 1-2 名 Flutter 开发） |
| **与 Web 端代码复用** | 高（共享组件库） | 中（业务逻辑可复用） | 低（需重写 UI） |
| **离线能力** | 中（IndexedDB，数据量受限） | 高（SQLite） | 高（SQLite） |
| **扫码体验** | 中（Web API 限制） | 高（原生相机） | 高（原生相机） |
| **2025 年生态成熟度** | 成熟 | 成熟（新架构 Fabric 已稳定） | 非常成熟（[参考](https://blog.csdn.net/nal/article/details/148654751)） |

## 决策结果

**推荐方案：PWA（一期）+ React Native（二期按需升级）**

### 理由

1. **一期需求 PWA 完全满足**：巡检核心功能（任务列表、检查项录入、拍照、离线）PWA 均可支持
2. **开发成本最低**：复用 React 技术栈和组件库，1 名前端工程师即可完成，与 Web 端共享 60%+ 代码
3. **快速上线**：PWA 开发周期 2-3 周，React Native 需要 4-6 周
4. **渐进增强策略**：一期用 PWA 快速验证巡检流程，如果后续需要 NFC/蓝牙等原生能力，再升级到 React Native（[参考](https://dev.to/sajan_kumarsingh_b556129/cross-platform-mobile-development-react-native-vs-flutter-vs-progressive-web-apps-in-2025-50am)）
5. **不选 Flutter 的原因**：团队技术栈是 React，引入 Flutter 需要学习 Dart，增加团队负担

### 升级触发条件

当以下任一需求出现时，启动 React Native 升级：
- 需要 NFC 标签读取（设备快速识别）
- 需要蓝牙连接（传感器直连读取）
- 需要后台精确定位（巡检轨迹自动记录）
- PWA 离线数据量超过 IndexedDB 限制（通常 50MB）
